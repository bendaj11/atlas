# Angular SDK

This guide shows how Angular code talks to its Host through the Atlas [SDK](../../introduction/glossary.md#sdk) (`@atlas/sdk`). It covers the everyday tasks in an App and in Host components. For every type and signature, see the [SDK reference](../../reference/sdk.md).

## Before you start

- You have an Angular App or Host generated by Atlas. See [Build an Angular App](app.md) or [Build an Angular Host](host.md).
- The Host team has told you which services its SDK provides, ideally as a shared TypeScript type in a package that the Host and Apps both compile against. This guide calls that type `CustomerHostSdk` and uses `@customer/host-sdk` as a placeholder for the package. The Host side of these services is set up in [Provide Host services through the SDK](host.md#4-provide-host-services-through-the-sdk).

## Read the SDK in a component

Call `injectAtlasSdk()` from `@atlas/sdk/angular` in any injection context of an App bootstrapped with `provideAtlasApp()`. The type argument describes the Host's custom members:

```ts
import { Component } from '@angular/core';
import { injectAtlasSdk } from '@atlas/sdk/angular';
import type { CustomerHostSdk } from '@customer/host-sdk';

@Component({
  selector: 'orders-toolbar',
  standalone: true,
  template: `<button type="button" (click)="save()">Save order</button>`,
})
export class OrdersToolbarComponent {
  readonly sdk = injectAtlasSdk<CustomerHostSdk>();

  async save(): Promise<void> {
    await this.sdk.orders.create();
    this.sdk.showToast('Order saved');
  }
}
```

Atlas adds `hostId`, `hostData`, `navigateTo()`, `events`, and `getWidget()` to every SDK. Use the SDK for Host services and communication between Apps. Keep App-internal state in normal Angular services.

If a custom SDK method calls other SDK members through `this`, write it as a regular function, not an arrow function, so Atlas can pass the Angular SDK object as its receiver. See the [SDK reference](../../reference/sdk.md) for details.

Host components can call `injectAtlasSdk()` too, once the runtime has created the SDK. See [Provide Host services through the SDK](host.md#4-provide-host-services-through-the-sdk).

## Read host data

Host data is a read-only object the Host shares with every App, such as the signed-in user or the current tenant. In Angular, `hostData` is a read-only Signal. Declare its fields in the SDK type and read them in a `computed` or a template:

```ts
import { Component, computed } from '@angular/core';
import { injectAtlasSdk } from '@atlas/sdk/angular';
import type { CustomerHostSdk } from '@customer/host-sdk';

@Component({
  selector: 'orders-user-badge',
  standalone: true,
  template: `{{ userName() }}`,
})
export class UserBadgeComponent {
  readonly sdk = injectAtlasSdk<CustomerHostSdk>();
  readonly userName = computed(() => this.sdk.hostData().user?.name ?? 'Guest');
}
```

In this example, `CustomerHostSdk` declares `hostData: { user: PublicUser | null | undefined }`. When the Host changes host data, the Signal updates. `hostData().hostId` and `hostData().name` are always present. The same data reaches Apps in React Hosts; see [Share host data with apps](../host-data.md) for how Hosts publish it.

## Navigate

Use Angular Router for screens inside your App. Use `navigateTo()` with an App ID to go to another App:

```ts
this.sdk.navigateTo('7c1e0f55-5d8a-4b7e-9d0e-3f2a1b6c9e41', { tab: 'open' });
```

See [Navigate to another App](routing.md#navigate-to-another-app).

## Send and receive events

Events are in-memory notifications between the Apps mounted in one Host. Use them for UI updates, such as refreshing a badge after an order is saved. Do not use them for durable business workflows; an App that is not mounted does not receive them.

Declare an event map, then pass it as the second type argument:

```ts
import { Component, DestroyRef, inject } from '@angular/core';
import { injectAtlasSdk } from '@atlas/sdk/angular';
import type { CustomerHostSdk } from '@customer/host-sdk';

type ProductEvents = {
  'orders.updated': { orderId: string };
  'cart.cleared': undefined;
};

@Component({
  selector: 'orders-events',
  standalone: true,
  template: `<button type="button" (click)="clearCart()">Clear cart</button>`,
})
export class OrdersEventsComponent {
  readonly sdk = injectAtlasSdk<CustomerHostSdk, ProductEvents>();

  constructor() {
    const onOrderUpdated = (payload: { orderId: string }) =>
      console.info('Order updated', payload.orderId);

    this.sdk.events.addEventListener('orders.updated', onOrderUpdated);
    inject(DestroyRef).onDestroy(() =>
      this.sdk.events.removeEventListener('orders.updated', onOrderUpdated),
    );
  }

  clearCart(): void {
    this.sdk.events.emit('cart.cleared');
  }
}
```

- `emit(type, payload)` sends an event. Events whose payload type is `undefined` take no payload.
- Always remove listeners when the component is destroyed. `sdk.events.once()` registers a listener that runs once and returns a function that cancels it.
- Prefix event names with a domain, such as `orders.`, and keep the event map in a shared package so senders and receivers compile against the same shape.

## Use App assets

For files in the App's `public/` folder, build URLs with the SDK so they work locally, on a CDN, and when [Columbus](../columbus.md) overrides a version:

```ts
import { Component } from '@angular/core';
import { injectAtlasSdk } from '@atlas/sdk/angular';

@Component({
  selector: 'orders-billboard',
  standalone: true,
  template: `<img [src]="billboardUrl" alt="" />`,
})
export class BillboardComponent {
  readonly sdk = injectAtlasSdk();
  readonly billboardUrl = this.sdk.assetUrl('billboards/plane.png');
  readonly libraryBaseUrl = this.sdk.assetBaseUrl();
}
```

Pass a path relative to `public/`, without a leading `/`: `public/billboards/plane.png` becomes `billboards/plane.png`. A path that leaves the App's published folder throws `ATLAS_ASSET_PATH_OUTSIDE_ARTIFACT`. Both functions need an App context; calling them from a Host component throws `ATLAS_APP_CONTEXT_MISSING`.

To use the same URLs in `src/app/app.config.ts`, before Angular dependency injection exists, call `createAtlasAppAssets(context)` from `@atlas/sdk`. The generated `createAppConfig()` already receives `context`. Read [Angular assets and styles](assets-and-styles.md) for CSS and template URLs.

## Use Widgets

A [Widget](../../introduction/glossary.md#widget) is a component that one App exports and other Apps or the Host render by ID. The owner can use Angular or React; the consumer does not need to know.

### Render a Widget

Create a Widget binding with `getWidget()`, then bind it to an element with the `WidgetOutlet` directive:

```ts
import { Component, computed, input } from '@angular/core';
import { injectAtlasSdk, WidgetOutlet } from '@atlas/sdk/angular';

interface OrderSummaryInputs {
  orderId: string;
}

@Component({
  selector: 'order-summary',
  standalone: true,
  imports: [WidgetOutlet],
  template: `<section [atlasWidget]="widget()"></section>`,
})
export class OrderSummaryComponent {
  readonly orderId = input.required<string>();
  readonly sdk = injectAtlasSdk();
  readonly widget = computed(() =>
    this.sdk.getWidget<OrderSummaryInputs>(
      '98abc74d-a11f-4eca-8255-c6f2f49e3d6e',
      { inputs: { orderId: this.orderId() } },
    ),
  );
}
```

Replace the UUID with the Widget ID that the owning team shares.

- `getWidget()` only creates a typed binding. `[atlasWidget]` mounts the Widget into its element, forwards changed inputs without remounting when the Widget supports updates, and unmounts it when Angular destroys the element. It works inside `@if` and `@for` blocks.
- Pass `loadingComponent` next to `inputs` to show your own component while the Widget loads. Without it, the Host's `renderWidgetLoading` renderer applies.

### Export a Widget

Generate a Widget inside an App. Replace the example UUID with your App ID from the App's `atlas.config.ts`:

```sh
npx atlas g widget order-status --app-id 2bea9c13-4899-4f93-9211-cd8c55e9c529
```

The generator creates `src/exported-widgets/order-status/` with `atlas.config.ts` (the Widget's UUID and name), `index.ts` (the default-exported standalone component, whose signal inputs receive the consumer's `inputs`), and `widget.config.ts` (the Widget's Angular providers). See [Widget files](project-structure.md#widget-files).

At build time, Atlas generates an entry for each Widget that calls `createExportedWidget(Widget, widgetConfig)` from `@atlas/sdk/angular`. For every mount, `createExportedWidget()` creates a separate Angular application with `provideAtlasApp()` plus your `widgetConfig` providers, renders the component into the Widget container, and forwards input changes with `setInput()`. If you delete `widget.config.ts`, the Widget starts with no extra providers.

Add providers the Widget needs, such as `provideHttpClient()`, to `widgetConfig`:

```ts
import type { ApplicationConfig } from '@angular/core';
import { provideHttpClient } from '@angular/common/http';

export const widgetConfig: ApplicationConfig = {
  providers: [provideHttpClient()],
};
```

Share the Widget ID and the inputs type with consuming teams. Treat the inputs as a public API and change them in backward-compatible ways. See [Exported widgets](../exported-widgets.md) for publishing, versions, and Widgets from other registries.

## Signal readiness

By default, Atlas treats an App as ready when `mount` finishes. If the first useful screen depends on data, call `injectAppLoaded()` and invoke the returned function when the screen is ready:

```ts
import { Component, inject, type OnInit } from '@angular/core';
import { injectAppLoaded } from '@atlas/sdk/angular';
import { OrdersStore } from './orders.store';

@Component({
  selector: 'orders-home',
  standalone: true,
  template: `...`,
})
export class OrdersHomeComponent implements OnInit {
  private readonly ready = injectAppLoaded();
  private readonly store = inject(OrdersStore);

  async ngOnInit(): Promise<void> {
    await this.store.loadInitialOrders();
    this.ready();
  }
}
```

Once you call `injectAppLoaded()`, you must call the returned function. Otherwise the App stays hidden, and Atlas shows the error UI after the resource timeout; see [The loading indicator never disappears](../../troubleshooting.md#the-loading-indicator-never-disappears).

## Test components that use the SDK

Create a mock environment with `mockAtlasEnvironment()` from `@atlas/testkit` and provide it with `provideMockAtlasEnvironment()` from `@atlas/testkit/angular`. Override only the SDK members the test uses:

```ts
import { TestBed } from '@angular/core/testing';
import { mockAtlasEnvironment } from '@atlas/testkit';
import { provideMockAtlasEnvironment } from '@atlas/testkit/angular';
import type { CustomerHostSdk } from '@customer/host-sdk';
import { OrdersToolbarComponent } from './orders-toolbar.component';

const showToast = jest.fn();
const environment = mockAtlasEnvironment<CustomerHostSdk>({
  sdk: { showToast },
});

TestBed.configureTestingModule({
  providers: [provideMockAtlasEnvironment(environment)],
});
const fixture = TestBed.createComponent(OrdersToolbarComponent);
```

See [Testing Apps and Hosts](../testing-apps-and-hosts.md#angular) for navigation, host data, readiness, and Host tests.

## API summary

These are the Angular entry points. Generated projects already use the lifecycle exports; you need them only when you replace generated wiring. See the [API reference](../../reference/api.md) for full signatures.

| Export                                                                                   | Package                  | Use it to                                                                                          |
| ---------------------------------------------------------------------------------------- | ------------------------ | -------------------------------------------------------------------------------------------------- |
| `injectAtlasSdk`                                                                         | `@atlas/sdk/angular`     | Read the Angular SDK, with `hostData` as a Signal and Angular Widget bindings.                     |
| `injectAppLoaded`                                                                        | `@atlas/sdk/angular`     | Delay App readiness until you call the returned function.                                          |
| `injectAtlasAppContext`                                                                  | `@atlas/sdk/angular`     | Read the App context, such as the mount `path` and the App manifest.                               |
| `WidgetOutlet`                                                                           | `@atlas/sdk/angular`     | The `[atlasWidget]` directive that mounts a Widget binding.                                        |
| `defineApp`                                                                              | `@atlas/sdk/angular`     | Wrap the App's bootstrap function as the Atlas App entry in `src/entry.ts`.                        |
| `provideAtlasApp`                                                                        | `@atlas/sdk/angular`     | Provide the SDK, App context, component style target, and optional location strategy.              |
| `provideAtlasAppContext`                                                                 | `@atlas/sdk/angular`     | Provide only the App context and set Angular's `APP_ID` to the App ID. `provideAtlasApp` calls it. |
| `provideAtlasSdk`                                                                        | `@atlas/sdk/angular`     | Provide only the SDK, as a value or a factory.                                                     |
| `createLocationStrategy`                                                                 | `@atlas/sdk/angular`     | Scope Angular Router to the App's mount path.                                                      |
| `createExportedWidget`                                                                   | `@atlas/sdk/angular`     | Turn a standalone component into a Widget entry. Atlas calls it in generated Widget entries.       |
| `defineAngularHost`                                                                      | `@atlas/runtime/angular` | Create the Host `mount` function in `src/bootstrap.ts`.                                            |
| `bootstrapAngularHost`, `startHost`                                                      | `@atlas/runtime/angular` | Start a Host at a lower level. Prefer `defineAngularHost`.                                         |
| `AtlasNavigationItemsService`                                                            | `@atlas/runtime/angular` | Read navigation items for custom Host navigation.                                                  |
| `AtlasHostLayout`, `AtlasRouteOutlet`, `AtlasSlot`, `AtlasNavigation`, `AtlasHostStatus` | `@atlas/runtime/angular` | Host anchors. See [Build the Host layout](host.md#3-build-the-host-layout).                        |
