# React SDK

This guide shows how React code talks to its Host through the Atlas [SDK](../../introduction/glossary.md) (`@atlas/sdk`). It covers the everyday tasks in an App and in Host components. For every type and signature, see the [SDK reference](../../reference/sdk.md).

## Before you start

- You have a React App or Host generated by Atlas. See [Build a React App](app.md) or [Build a React Host](host.md).
- The Host team has told you which services its SDK provides, ideally as a shared TypeScript type in a package that the Host and Apps both compile against. This guide calls that type `CustomerHostSdk`. The Host side of these services is set up in [Provide Host services through the SDK](host.md#4-provide-host-services-through-the-sdk).

## Read the SDK in a component

Call `useAtlasSdk()` from `@atlas/sdk/react` in any component that Atlas renders, either in an App or in the Host layout:

```tsx
import { useAtlasSdk } from '@atlas/sdk/react';

export interface CustomerHostSdk {
  orders: { create(): Promise<void> };
  showToast(message: string): void;
}

export function SaveOrderButton() {
  const sdk = useAtlasSdk<CustomerHostSdk>();

  return (
    <button
      type="button"
      onClick={async () => {
        await sdk.orders.create();
        sdk.showToast('Order saved');
      }}
    >
      Save order
    </button>
  );
}
```

The type argument describes the Host's custom members; Atlas adds `hostId`, `hostData`, `navigateTo()`, `events`, and `getWidget()` to every SDK. Use the SDK for Host services and communication between Apps. Keep App-internal state in normal React state, context, and hooks.

`useAtlasSdk()` throws an error with the code `ATLAS_SDK_CONTEXT_MISSING` when it runs outside an Atlas-rendered tree, for example in a separate React root that you create yourself.

## Read host data

Host data is a read-only object the Host shares with every App, such as the signed-in user or the current tenant. Declare its fields in the SDK type and read them from `sdk.hostData`:

```tsx
import { useAtlasSdk } from '@atlas/sdk/react';

interface CustomerHostSdk {
  hostData: {
    user: { displayName: string } | null | undefined;
  };
}

export function Greeting() {
  const sdk = useAtlasSdk<CustomerHostSdk>();
  const user = sdk.hostData.user;

  if (user === undefined) return <p>Loading…</p>;

  if (user === null) return <p>You are signed out.</p>;

  return <p>Hello, {user.displayName}</p>;
}
```

When the Host changes host data, Atlas re-renders every component that called `useAtlasSdk()`. You do not subscribe yourself. `sdk.hostData.hostId` and `sdk.hostData.name` are always present. The same data reaches Apps in Angular Hosts; see [Share host data with apps](../host-data.md) for how Hosts publish it.

## Navigate

Use React Router for screens inside your App. Use `sdk.navigateTo()` with an App ID to go to another App:

```tsx
sdk.navigateTo('7c1e0f55-5d8a-4b7e-9d0e-3f2a1b6c9e41', { tab: 'open' });
```

See [Navigate to another App](routing.md#navigate-to-another-app).

## Send and receive events

Events are in-memory notifications between the Apps mounted in one Host. Use them for UI updates, such as refreshing a badge after an order is saved. Do not use them for durable business workflows; an App that is not mounted does not receive them.

Declare an event map, then pass it as the second type argument:

```tsx
import { useEffect, useState } from 'react';
import { useAtlasSdk } from '@atlas/sdk/react';

type ProductEvents = {
  'orders.updated': { orderId: string };
  'cart.cleared': undefined;
};

export function LastUpdatedOrder() {
  const sdk = useAtlasSdk<{}, ProductEvents>();
  const [orderId, setOrderId] = useState<string>();

  useEffect(() => {
    const listener = (payload: { orderId: string }) =>
      setOrderId(payload.orderId);

    sdk.events.addEventListener('orders.updated', listener);

    return () => sdk.events.removeEventListener('orders.updated', listener);
  }, [sdk]);

  return (
    <>
      <p>Last updated order: {orderId ?? 'none'}</p>
      <button type="button" onClick={() => sdk.events.emit('cart.cleared')}>
        Clear cart
      </button>
    </>
  );
}
```

- `emit(type, payload)` sends an event. Events whose payload type is `undefined` take no payload.
- Always remove listeners in the effect cleanup. `sdk.events.once()` registers a listener that runs once and returns a function that cancels it.
- Prefix event names with a domain, such as `orders.`, and keep the event map in a shared package so senders and receivers compile against the same shape.

## Use App assets

For files in the App's `public/` folder, build URLs with the SDK so they work locally, on a CDN, and when [Columbus](../columbus.md) overrides a version:

```tsx
const sdk = useAtlasSdk();

const billboardUrl = sdk.assetUrl('billboards/plane.png');
const cesiumBaseUrl = sdk.assetBaseUrl();
```

Pass a path relative to `public/`, without a leading `/`: `public/billboards/plane.png` becomes `billboards/plane.png`. A path that leaves the App's published folder throws `ATLAS_ASSET_PATH_OUTSIDE_ARTIFACT`. Both functions need an App context; calling them from a Host component throws `ATLAS_APP_CONTEXT_MISSING`.

For images and CSS in `src/`, use Vite imports instead. See [React assets and styles](assets-and-styles.md).

## Use Widgets

A [Widget](../../introduction/glossary.md) is a component that one App exports and other Apps or the Host render by ID. The owner can use Angular or React; the consumer does not need to know.

### Render a Widget

`sdk.getWidget()` returns a React component. Its props are the Widget's inputs:

```tsx
import { useAtlasSdk } from '@atlas/sdk/react';

interface OrderSummaryProps {
  orderId: string;
}

function SummaryPlaceholder() {
  return <p>Loading summary…</p>;
}

export function OrderSidebar({ orderId }: OrderSummaryProps) {
  const sdk = useAtlasSdk();
  const OrderSummary = sdk.getWidget<OrderSummaryProps>(
    '98abc74d-a11f-4eca-8255-c6f2f49e3d6e',
    { loadingComponent: SummaryPlaceholder },
  );

  return <OrderSummary orderId={orderId} />;
}
```

Replace the UUID with the Widget ID that the owning team shares.

- Atlas returns the same component for the same Widget ID and `loadingComponent`, so calling `getWidget()` during render is safe.
- The component mounts the Widget when it renders, forwards changed props without remounting, and unmounts the Widget when React removes it. It works inside conditions and lists.
- `loadingComponent` renders while the Widget code loads. Without it, the Host's `renderWidgetLoading` renderer applies.
- If the Widget cannot mount, the component throws during render. Wrap Widgets in an error boundary when a failure should not replace the surrounding screen.

### Export a Widget

Generate a Widget inside an App. Replace the example UUID with your App ID from the App's `atlas.config.ts`:

```sh
npx atlas g widget order-summary --app-id 2bea9c13-4899-4f93-9211-cd8c55e9c529
```

The generator creates `src/exported-widgets/order-summary/atlas.config.ts`, which holds the Widget's UUID and name, and `index.tsx`, whose default export is the Widget component. Its props are the Widget's inputs. You do not write any mount code: at build time, `createReactAppViteConfig` generates an entry for each folder in `src/exported-widgets/` and exposes it through Native Federation.

Share the Widget ID and the props type with consuming teams. Treat the props as a public API and change them in backward-compatible ways. See [Exported widgets](../exported-widgets.md) for publishing, versions, and Widgets from other registries.

## Signal readiness

By default, Atlas treats an App as ready as soon as it mounts. If the first useful screen depends on data, call `useAppLoaded()` and invoke the returned function when the screen is ready:

```tsx
import { useEffect } from 'react';
import { useAppLoaded } from '@atlas/sdk/react';

export function OrdersHome() {
  const markLoaded = useAppLoaded();

  useEffect(() => {
    let active = true;

    loadInitialOrders().then(() => {
      if (active) markLoaded();
    });

    return () => {
      active = false;
    };
  }, [markLoaded]);

  return <OrdersTable />;
}
```

`loadInitialOrders` and `OrdersTable` stand for your own code. Once you call `useAppLoaded()`, you must call the returned function. Otherwise Atlas waits until the resource timeout and then shows the error UI; see [The loading indicator never disappears](../../troubleshooting.md#the-loading-indicator-never-disappears). `useAppLoaded()` throws `ATLAS_APP_CONTEXT_MISSING` outside a mounted App.

## Test components that use the SDK

Render components inside `MockAtlasEnvironmentProvider` from `@atlas/testkit/react`, with an environment from `mockAtlasEnvironment()`. Override only the SDK members the test uses. This Jest test renders `SaveOrderButton` from the first example on this page, saved as `save-order-button.tsx`:

```tsx
import type { ReactNode } from 'react';
import { render } from '@testing-library/react';
import { mockAtlasEnvironment } from '@atlas/testkit';
import { MockAtlasEnvironmentProvider } from '@atlas/testkit/react';
import { SaveOrderButton, type CustomerHostSdk } from './save-order-button';

const showToast = jest.fn();
const environment = mockAtlasEnvironment<CustomerHostSdk>({
  sdk: { showToast },
});

render(<SaveOrderButton />, {
  wrapper: ({ children }: { children: ReactNode }) => (
    <MockAtlasEnvironmentProvider environment={environment}>
      {children}
    </MockAtlasEnvironmentProvider>
  ),
});
```

See [Testing Apps and Hosts](../testing-apps-and-hosts.md) for navigation, host data, readiness, and Host tests.

## API summary

These are the React entry points. Generated projects already use the lifecycle exports; you need them only when you replace generated wiring. See the [API reference](../../reference/api.md) for full signatures.

| Export                                                                                   | Package                        | Use it to                                                                                             |
| ---------------------------------------------------------------------------------------- | ------------------------------ | ----------------------------------------------------------------------------------------------------- |
| `useAtlasSdk`                                                                            | `@atlas/sdk/react`             | Read the SDK in a component that Atlas renders.                                                       |
| `useAppLoaded`                                                                           | `@atlas/sdk/react`             | Delay App readiness until you call the returned function.                                             |
| `useAtlasStyleTarget`                                                                    | `@atlas/sdk/react`             | Get the node where CSS-in-JS libraries should insert styles.                                          |
| `defineApp`                                                                              | `@atlas/sdk/react`             | Define the lifecycle of an App without inner routing.                                                 |
| `createRoutedApp`                                                                        | `@atlas/sdk/react`             | Define the lifecycle of an App with a React Router memory router.                                     |
| `createRouterOptions`                                                                    | `@atlas/sdk/react`             | Get `initialEntries` for `createMemoryRouter` from the App context.                                   |
| `connectRouter`                                                                          | `@atlas/sdk/react`             | Keep a custom router in sync with the Host URL. `createRoutedApp` calls it for you.                   |
| `readAtlasInnerUrl`                                                                      | `@atlas/sdk/react`             | Read the App-relative URL (inner path plus the Host's query string and hash).                         |
| `defineExportedWidget`                                                                   | `@atlas/sdk/react`             | Define a Widget entry by hand instead of using the generated one.                                     |
| `AtlasSdkProvider`                                                                       | `@atlas/sdk/react`             | Provide an SDK to a React tree that Atlas does not render.                                            |
| `AtlasSdkContext`                                                                        | `@atlas/sdk/react`             | Read the raw SDK from React context, for example in a class component. It has no React `getWidget()`. |
| `createReactWidgetEntries`                                                               | `@atlas/sdk/federation-config` | Generate Widget entries in a custom Vite configuration.                                               |
| `defineReactHost`                                                                        | `@atlas/runtime/react`         | Create the Host `mount` function in `src/bootstrap.tsx`.                                              |
| `useAtlasNavigationItems`                                                                | `@atlas/runtime/react`         | Read navigation items for custom Host navigation.                                                     |
| `AtlasHostLayout`, `AtlasRouteOutlet`, `AtlasSlot`, `AtlasNavigation`, `AtlasHostStatus` | `@atlas/runtime/react`         | Host anchors. See [Build the Host layout](host.md#3-build-the-host-layout).                           |
